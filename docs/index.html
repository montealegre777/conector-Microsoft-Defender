¿Qué es y para qué sirve?

El conector Microsoft Defender permite que el agente de Ruvic consulte y responda a amenazas detectadas por Defender for Endpoint — listar alertas, ver el detalle de una máquina, y aislar/liberar un dispositivo de la red.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué alertas críticas hubo hoy?"
  • "¿Cuál es el estado de esta máquina?"
  • "Aísla este dispositivo, está comprometido."

Operaciones soportadas:

OperaciónQué hace
cybersecurity.list_alertsLista alertas, con filtro de severidad opcional
cybersecurity.get_machine_infoConsulta el detalle de una máquina
cybersecurity.set_device_isolationAísla o libera un dispositivo de la red
El aislamiento está bloqueado por defecto Aislar un dispositivo de la red es una acción real y disruptiva. Este conector la bloquea salvo que actives "Permitir aislar/liberar dispositivos" explícitamente al configurarlo.

Prerrequisitos

  • Un tenant de Microsoft Defender for Endpoint con licencia activa.
  • Acceso a Azure Portal (Microsoft Entra ID) para registrar una aplicación.
  • Permisos para otorgar "admin consent" sobre los permisos de API (o alguien que pueda hacerlo).

Configuración en el fabricante

  1. Registra una aplicación en Azure AD. Azure Portal → Microsoft Entra ID → App registrations → New registration.
  2. Genera un Client Secret. Certificates & secrets → New client secret. Cópialo de inmediato, solo se muestra una vez.
  3. Agrega los permisos de la API WindowsDefenderATP. API permissions → Add a permission → APIs my organization uses → busca "WindowsDefenderATP". Elige Application permissions (no delegadas).
  4. Selecciona los permisos mínimos necesarios. "Alert.Read.All" y "Machine.Read.All". Agrega "Machine.Isolate" solo si vas a permitir el aislamiento.
  5. Otorga el consentimiento de administrador. Clic en "Grant admin consent" — sin este paso, los permisos de aplicación no funcionan aunque estén "agregados".

Permisos requeridos

Permiso de aplicaciónPara qué lo usa el conector
Alert.Read.AllNecesario para list_alerts
Machine.Read.AllNecesario para get_machine_info
Machine.IsolateSolo necesario si activas el aislamiento de dispositivos

Usa permisos de "Application" (no "Delegated") — este conector corre sin un usuario interactivo.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Microsoft Defender y pulsa Configurar.

Completa el Tenant ID, Client ID y Client Secret. Deja "Permitir aislar/liberar dispositivos" desactivado salvo que tengas una necesidad real confirmada.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a [URL de la API]".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Qué alertas recientes hay?"

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Azure AD rechazó la autenticación"Tenant ID, Client ID o Client Secret incorrectos, o el secret expiró.
"Permisos insuficientes" (HTTP 401/403)Falta otorgar "Grant admin consent" sobre los permisos de la API WindowsDefenderATP — agregarlos no basta, hay que darles el consentimiento.
"El aislamiento de dispositivos está bloqueado por defecto"Es la protección de seguridad funcionando — activa "Permitir aislar/liberar dispositivos" si realmente necesitas esta función.

Preguntas frecuentes y notas de seguridad

¿Qué pasa si aíslo un dispositivo por error?

Se puede revertir llamando a la misma función con la dirección contraria (liberar). Aun así, aislar un dispositivo real interrumpe su conectividad de red mientras dura el aislamiento — confirma siempre antes de ejecutarlo.

¿Dónde queda guardado el Client Secret?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

¿Qué hago si el secret se compromete?

Ve a Azure Portal → la App Registration → Certificates & secrets, elimina el secret comprometido, genera uno nuevo, y actualízalo en el formulario del conector.

Buenas prácticas Otorga solo los permisos mínimos necesarios; deja el aislamiento desactivado salvo necesidad real; y confirma explícitamente con el usuario antes de aislar un dispositivo — es la acción más disruptiva de este conector.
